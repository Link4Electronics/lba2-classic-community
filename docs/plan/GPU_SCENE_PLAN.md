# Moving scene drawing onto the GPU renderers

Status: Phase 2 Implemented (interior room bricks, bodies and NZW polys behind `GpuScene`, default off). Phase 3 is In Progress — interior brick iso-depth, the scene-interior mark, opaque world sprites (`GpuRenderer_DrawSprite`: TYPE_OBJ_SPRITE / TYPE_OBJ_ANIM_3DS / 1:1 TYPE_EXTRA), the front-wall re-blit moved into the FBO (`GpuRenderer_DrawBrickOver`, the brick's own quad re-submitted depth-free after the body, `CopyMask` kept as the software fallback) with the interior `Screen` plate reduced to the on-demand one the 2D modals build (`AffGrille_BuildScreenPlate` + `DefaultBoxOneClear` under `GpuRenderer_IsSceneInterior`), the R8 present conversion (palette-index Log upload, LUT in `present.frag.glsl`), the exterior inventory plate (`AffGrilleExt_BuildScreenPlate` under `GpuRenderer_SetSoftwarePolys`), the behaviour-modal plate + opaque rect (`MenuComportement` in [COMPORTE.CPP](../../SOURCES/COMPORTE.CPP)), and blend sprites (`GpuRenderer_DrawBlendSprite`, mode-8 fragment), and scaled opaque sprites (`GpuRenderer_DrawScaleSprite`: the `GpuBlend_Walk` run of `ScaleSprite`'s sampling packed as a depth-tested quad), and exterior flow particles (`GpuRenderer_DrawFlowDot`: each dot as two row quads carrying the software sweep's row-constant `ZBufBoxOverWrite2` depth), and HUD text (`GpuRenderer_DrawHudText` over the `AffScene` incrust loop and `DrawBulle`) have landed; readback deletion and the staging-upload shrink are still Proposed. [RENDERER.md](../RENDERER.md) remains the reference for what the engine does today.

## Goal

Today only the exterior 3D scene reaches the GL / SDL3 GPU backends; interiors, sprites, HUD and text rasterize in the 1997 software path and composite over the GPU frame as the Log overlay. With one flag on — cfg key `GpuScene`, cvar `gpuscene`, default 0 — scene drawing moves onto the GPU for both backends, phase by phase. With the flag off, every new branch is dead: the default build stays byte-identical to today's hybrid, as the flag-gating rule requires.

Three costs are being removed, in the order they matter:

1. The interior room is thousands of CPU RLE sprite blits per frame (brick grid), scaling with the player's resolution while the exterior already scales on the GPU.
2. Every exterior frame drains the GPU pipeline for a depth readback (`GpuRenderer_ReadbackDepthBuffer`) so software sprites can test terrain occlusion.
3. Every frame converts the whole Log to ARGB on the CPU, stages it and uploads it, even where the Log covers most of the screen.

A note on the premise: the interior cube is not one texture. Bricks are individually RLE-encoded palette sprites (`AffGraph` in [GRAPH.CPP](../../LIB386/SVGA/GRAPH.CPP)), drawn in grid order, with walls in front of actors re-blitted through a second, mask-gated blit (`CopyMask` via `DrawOverBrick`). The migration turns the base grid blits into a batch of textured screen quads; the re-blit stayed software through the first phases — the present order already made it correct, since Log composites over the FBO — and joined the same batch in phase 3, which is what let the per-frame `Screen` plate go.

## Invariants the design keeps

- **Present order is the constraint.** The GPU frame presents first, the Log overlay paints on top, palette index 0 transparent. Anything that must appear over scene content lives in the Log until everything beneath it has moved too — so phases migrate whole layers in an order where every intermediate split is order-correct, never screen-by-screen guesses.
- **All shared machinery lives in [GPURENDERER_COMMON.CPP](../../LIB386/COMMON/GPURENDERER_COMMON.CPP).** Batching, atlas state, quad submission, the darken-span mode: one implementation. The two backends only grow a vtable operation where GL and SDL3 GPU genuinely differ (buffer/texture creation). No quad path is written twice.
- **Software paths stay untouched when the flag is off.** Hooks are added at draw sites the flag gates; the ASM equivalence tests keep testing the software fillers exactly as now.
- **Pixel rules come from the software blitters.** A quad must reproduce `AffGraph` output: same positions (integer, `Map2Screen` + hotX/hotY), same palette mapping at present time (the brick atlas follows the poly path's CLUT scheme — palette-index texture resolved through the same LUT GPU content already uses, so palette fades keep affecting the room), nearest sampling, the RLE's skip blocks becoming atlas alpha. The re-blit's gate is `CopyMask`'s mask bank in software; the quad needs no second texture for it, because `CalcGraphMsk` builds that bank from the brick's own RLE spans — the same spans the atlas valid channel (G) records, so the fragment's `G == 0` discard is the identical gate.
- **Bookkeeping never moves to the GPU.** `AffBrickBlock` both draws and buckets the brick into `ListBrickColon` for `DrawOverBrick`; the hook replaces only the blit, the bucketing stays.

## Why the phases are ordered this way

The Log-over-FBO present order decides what can move first:

- The room can move first: bodies, sprites and HUD already draw after it, and they keep drawing into the Log, which presents on top — the same relative order as today. The re-blit walls started by duplicating room pixels that now live in the FBO while still painting into the Log, so the composite was unchanged; phase 3 submits them into the batch instead, which is what let the per-frame plate go.
- Bodies can follow: the front walls keep landing over them — in the Log until phase 3, then as a depth-free quad submitted after the body — so the wall-in-front case needs no body depth either way. Bodies keep the exterior scheme (painter order, `GEQUAL`, no depth write). The one known approximation is body-versus-sprite order when a sprite should paint behind a body — the same approximation the GPU exteriors already ship with.
- Sprites/HUD move last among scene layers, and that is the phase that deletes the depth readback: with terrain and room depth both in the FBO, sprite quads depth-test there directly. Only when the Log is empty of scene content can the per-frame staging upload shrink or go away.
- Interior shadows need no depth: the original interior `ShadeSpan` is a flat darken (`ShadeBoxBlk`) with no Z test, unlike the exterior's depth-tested spans. The split is pixel-preserving: the same spans darken the FBO (where the room now lives) through the existing `GpuRenderer_Shadow*` machinery in a new no-depth mode, while `ShadeBoxBlkOverlay` darkens whatever non-zero actor pixels sit in the Log (index 0 is the overlay's transparent hole — left alone so the FBO shows through; plain `ShadeBoxBlk` would map 0 through opaque `clut[0]` and paint solid holes) — each buffer receives exactly the darken its pixels received when they shared one buffer.
- Interior depth stays on the CPU throughout the first phases: the `PtrZBuffer` backing store is dual-use for brick/cube data and feeds `DrawOverBrick`'s Z-masks, so no readback is introduced for interiors until something actually needs it.

## Phases

**Phase 1 — interior room to the FBO (Implemented).** Flag-gated hooks at the base brick blit sites in [GRILLE.CPP](../../SOURCES/GRILLE.CPP) (`AffBrickBlock`, `AffBrickBlockOnly`) call `GpuRenderer_DrawBrick`, which packs the cube's `BufferBrick` bank into an RG8 atlas (R = palette index, G = valid; AffGraph RLE skips leave G = 0) and submits screen-space quads batched as polyMode 7. `InitGrille` hands the bank over after `LoadUsedBrick`; `FreeGrille` drops it. `RefreshGrille` already clears the FBO for both cube modes, and the `AFF_ALL` path's `Cls` keeps the Log clean for full frames. `DrawOverBrick`'s re-blit (through `CopyMask`), Z-masks, bodies, sprites, GRM incrusts and HUD all stay in the Log — phase 3 moves the re-blit into the FBO and leaves `CopyMask` as the software fallback. Interior shadow spans gain the no-depth COMMON mode (`GpuRenderer_ShadowBeginFlat`) with the dual `ShadeSpan` described above. Success criteria: flag off, byte-identical (host tests green); flag on, harness screenshots in an interior cube visually match flag off at the same tick, on both backends.

**Phase 2 — interior bodies and NZW polys to the FBO (Implemented).** The `AffOneObject` / `TYPE_DART` gates in [OBJECT.CPP](../../SOURCES/OBJECT.CPP) open the 3D pass for `CUBE_INTERIEUR` while the flag is on (today's exterior-only gate gains `GpuScene AND CubeMode == CUBE_INTERIEUR`), and COMMON's intake keys on "the FBO has room content this frame": `GpuRenderer_RenderTriangleList`'s `s_fboHasTerrain` condition gains its interior sibling `s_fboHasRoom`, set when `GpuRenderer_DrawBrick` successfully enqueues a quad, cleared by `GpuRenderer_ClearFBO` and the lifecycle resets that already clear `s_fboHasTerrain`. No depth is required — interior bodies use `TYPE_ISO` so `GetZO3`/`GetZO4` leave `Pt_ZO` alone, the cleared depth stays farthest, and front-wall re-blits still land in the Log above the bodies. The `AFF_ALL` path snapshots the clean room and the `AFF_OBJETS` head restores it (no `ReadbackDepthBuffer`, no `DrawAnimatedPolys` — exterior-only), so static frames start from the room rather than the previous frame's bodies. Success: screenshots match, including an actor standing in a doorway with a wall in front.

**Phase 3 — sprites and text to the FBO, readback deleted (In Progress).** Opaque world sprites first: `GpuRenderer_DrawSprite` packs a single AffGraph or 1:1 ScaleSprite entry into a separate RG8 page (same mode-7 fragment path; `GpuDrawParams.spriteAtlas` selects brick vs sprite bind) and submits a screen-space quad. Interior takes no depth-test/write (software `AffGraph` never Z-tests; front walls stay `DrawRecover3`); exterior `GEQUAL`-tests terrain depth with no depth-write. Hooks sit in `AffOneObject` only — `TYPE_OBJ_SPRITE`, `TYPE_OBJ_ANIM_3DS`, and the opaque branch of `TYPE_EXTRA` — so HUD sites (`COMPORTE`, `INVENT`, `INCRUST`, `GAMEMENU`) stay in Log; the scaled branch of those opaque draws (`ScaleFactorSprite != 65536`, landed as `GpuRenderer_DrawScaleSprite`) runs `GpuBlend_Walk` to reproduce `ScaleSprite`'s 16.16 sampling and `Screen*` publication into a scratch buffer, shelf-packs the walked rect (R = walked source index, G = index != 0) and batches the quad exactly like `DrawSprite`'s, so terrain occlusion is the FBO `GEQUAL` test instead of a `ZBufBoxOverWrite2` pass and the Log punch fires only on non-zero walk texels (`EXTRA_TRANSPARENT` moves to the blend path below). On success the clipped opaque footprint in Log is punched to index 0 so the present shows the FBO quad; interior still runs `DrawRecover3` for the front-wall re-blit. The front-wall re-blit moves into the FBO: `DrawOverBrick` / `DrawOverBrick3` / `DrawOverBrickCage` route through `GpuRenderer_DrawBrickOver`, which re-submits the brick's own quad as `GPU_BRICKOVER_TYPE` — no depth test or depth write, so it lands over the body in batch order exactly as the mask-gated `CopyMask` copy did — and returns 0 whenever the flag is off, no backend is live or the pack fails, leaving the caller's `CopyMask` in charge. That removes the per-frame `Screen` plate: `AFF_ALL` mirrors the empty `Log` into `Screen` on both marks, and `DefaultBoxOneClear` under `GpuRenderer_IsSceneInterior` keeps `BoxClean` clearing rather than pasting a plate over FBO bodies. The companion R8 present sub-phase (landed): `PresentFrame` hands Log's raw palette indices to `GpuRenderer_Present(indexed=TRUE)` and the present shader resolves colour through the LUT, deleting the CPU Log→ARGB conversion; opaque overlay rects are applied in the shader (`indexedTexel` + `GpuRenderer_SetOverlayOpaqueRect`). The exterior inventory plate (`AffGrilleExt_BuildScreenPlate`) rebuilds a software `Screen` plate before `OpenInventory` when the backend is active, because exterior `AFF_ALL` ends with `CopyScreen(Log, Screen)` while Log was cleared for the FBO composite — without the plate `ShadeBoxBlk` would darken zeros to a flat shade instead of the scene; `GpuRenderer_SetSoftwarePolys` forces `Fill_Poly`'s hook to yield so the plate pass stays in Log indices. The behaviour (CTRL) modal (`MenuComportement`) takes the same on-demand plate (exterior rebuilds the terrain plate into Screen then copies to Log; interior rebuilds the room plate itself, since `AFF_ALL` no longer builds one — its `BackupScreen(TRUE)` would otherwise paste zeros over the plate before the shade runs) and pins the box + info bar with `GpuRenderer_SetOverlayOpaqueRect` so cadre strokes and empty bars present as black rather than transparent. Blend sprites (landed): `GpuRenderer_DrawBlendSprite` in [GPURENDERER_COMMON.CPP](../../LIB386/COMMON/GPURENDERER_COMMON.CPP) walks the sprite with the host-tested `GpuBlend_Walk` (golden test `tests/gpu_blend_walk`), packs each rect texel's source index beside the live `Log` index, uploads those pages plus a rect copy of the scene colour (alpha byte = destination index), punches the `Log` footprint to 0 only after the copy succeeds, and draws a mode-8 quad whose fragment reproduces `ScaleSpriteTransp`: discard on source 0, the `Log` byte wins over scene alpha, `PtrTransPal` row = source / column = destination, result index written back into alpha so a following blend sprite chains on top. Colour and alpha are replaced outright (`blend = 0`) with no depth-test or depth-write — software composes into `Log` unconditionally and `DrawRecover3` never follows a blend sprite. Two backend defects surfaced in the harness A/B and are fixed in this slice: `GL_TexUpdateBlendLog` forces unpack alignment to 1 before uploading its 2-byte rows (an odd rect width scrambled every row after the first), and the GL clip scissor rounds its mapped edges outward instead of truncating (a truncated edge dropped the top device row of any window whose mapped height landed off-integer — which is every blend rect, so the topmost row of every blend sprite went undrawn). Verified per draw with a CPU-oracle self-check on the GL run — staged buffers byte-identical to the GPU textures, composed result alpha equal to `transp[src][log ? log : dst]`, source-0 untouched, 183/183 draws — and with a GL/SDL3 harness A/B whose trail region is pixel-identical; the software leg stays a visual/structural comparison because wall-clock-driven Life scripts drift a pixel or two between backends.
 Flow particles (landed): `AffParticleFlow` ([FLOW.CPP](../../SOURCES/FLOW.CPP)) defers its exterior dots under the flag — each projected dot collects its screen position and colour, and the batch draws after the loop through `GpuRenderer_DrawFlowDot` in [GPURENDERER_COMMON.CPP](../../LIB386/COMMON/GPURENDERER_COMMON.CPP), one two-row quad pair per dot carrying `GetRecoverDepth`'s z0/z1 expanded with the software sweep's `Fill_ZBuffer_Factor`/`IncZ`/`>>16` into a per-row `zoTop`/`zoBot`, so the FBO `GEQUAL` test decides exactly where `ZBufBoxOverWrite2`'s row-constant test kept the dot (one quad across both rows would interpolate depth diagonally against a per-scanline decision). Each dot shelf-packs a 2×2 sprite-page pair (R = colour, G = colour != 0) and punches the same 2×2 `Log` footprint `BoxFlow` would; a dot `BoxFlow`'s clip would have rejected is consumed at that same test, a full atlas shelf falls back to software `BoxFlow`, the object's `DrawRecover` box still runs for its `BoxMovingAdd` dirty-box contract, and interior/hybrid cubes draw immediately at zero depth through the same fallback. Verified with the harness A/B: GL flag-on byte-identical to HEAD on flow cubes (60, 30, 80, 12, 140, 21, 44, 93, 151, 165), flag-off byte-identical, and SDL3 differing from its HEAD only where HEAD GL and HEAD SDL3 already disagree — the pre-existing cross-backend depth-rounding class — with the new SDL3 pixels matching GL.

Font/HUD text (landed): `GpuRenderer_DrawHudText` in [GPURENDERER_COMMON.CPP](../../LIB386/COMMON/GPURENDERER_COMMON.CPP) mirrors `Font` / `AffMask` / `ClippingMask` — a cursor walk for ink bounds and the `Screen*` publication a visible glyph leaves behind (a fully outside glyph leaves the previous one, spaces advance by `InterSpace`), then each glyph's RLE decoded into one shelf-reserved sprite page (R = `ColMask`, G = 1 on written texels, the slot zeroed first so a stale texel can never punch) and batched as an opaque sprite at `ZO` 0: exterior `GEQUAL` passes at the nearest depth with no depth-write and interior takes no test, so terrain and room never Z-occlude a HUD glyph. The `Log` punch fires only on G = 1 texels inside clip ∩ bounds, so the present composites the FBO glyph through the same hole software left. It returns 1 when consumed — including spaces-only and fully clipped strings, where `Font` would have drawn nothing — and 0 otherwise, and the caller falls back to `Font` unchanged; an atlas shelf with no room is one such 0. The callers are the `AffScene` incrust loop's `INCRUST_NUM` / `INCRUST_TEXT` (shadow + colour) / `INCRUST_SYS_TEXT` / `INCRUST_CMPT` sites and the `INCRUST_SPRITE` site in [OBJECT.CPP](../../SOURCES/OBJECT.CPP) (its blit is `PtrAffGraph`), plus `DrawBulle` in [INCRUST.CPP](../../SOURCES/INCRUST.CPP), each behind `TryGpuIncrustText` / `TryGpuIncrustSprite`. Both helpers decline when the flag is off, no backend is live, or a modal overlay rect is pinned (`GpuRenderer_IsOverlayOpaque` mirrors the present shader's `uOpaqueRect` test: the index-0-as-opaque-black rule inside the pinned rect would surface the punch as black instead of the glyph); `TryGpuIncrustSprite` splits the banks the way `PtrAffGraph` does (`sprite >= 100` → goodies bank, raw format 0, else raw bank) and routes a scaled raw sprite through `GpuRenderer_DrawScaleSprite`. Text that never passes through the incrust loop — the game menu's rows, the dialogue, the pause menu, the inventory and behaviour plates — stays in the Log as before. Verified with the harness A/B: a staged mecha-penguin countdown (`INCRUST_NUM`) renders byte-identical between flag-on and HEAD flag-on on GL, flag-off byte-identical to HEAD flag-off, SDL3 flag-on byte-identical to HEAD SDL3 flag-on, and the `ui inventory` modal capture byte-identical between flag-on, flag-off and HEAD flag-off (the opaque-rect gate); the standard recipe's only SDL3 delta is 9 px inside the pre-existing cross-backend class, matching GL at those coordinates.

Still open: skipping `GpuRenderer_ReadbackDepthBuffer` and its consumers, and the staging-upload shrink. The consumer list, after the flow move: the `ZBufBoxOverWrite2` color-0 hole trick still runs over the exterior Log — `TYPE_FLOW` objects still call `DrawRecover` after their GPU dots (its `BoxMovingAdd` dirty-box contract does not depend on the dots) and the recovery passes whose boxes span software Log content still read the depth — the body recovery's `flagbox` return additionally drives the camera-follow occlusion test (`TestNumObjFollow` in `AffOneObject`, only for `NumObjFollow`), so a consumer of the readback is camera behavior and not only pixels — and `LineRain` (`AffRain` in storm exteriors) reads `PtrZBuffer` directly for both its per-pixel terrain test and its splash collision against the readback's depth; all of it must move or be gated before the readback can go.

**Phase 4 — menus and text dialogs: evaluate, expect to defer.** Moving a menu screen requires the whole screen to move at once (backdrop, plasma, rows, sprites), and the win is small: menus are cheap today, the plasma is CPU-generated so it costs an upload either way, and font rasterization risk lands squarely on the highest-visibility UI. The in-game text dialog is a candidate only after Phase 3, drawn as a UI pass with depth testing off. The recommendation is to measure after Phase 3 and leave this phase unstarted unless the numbers argue for it.

## Flag and surfaces

- cfg key `GpuScene`, cvar `gpuscene`, default 0: a `BootSettings` row in [CONFIG_FILE.CPP](../../SOURCES/CONFIG_FILE.CPP) beside `RenderQuality`/`GpuTexFilter`, with the global beside `DisplayTexFilter`/`RenderQuality` in [RENDER_GL.CPP](../../LIB386/GL/RENDER_GL.CPP) — the established home for player-facing GPU toggles — read by COMMON and the SOURCES hook sites.
- A Display submenu row (Quality-style cycle or toggle) is an optional follow-up once the flag proves itself; cfg + cvar first.
- No backend-specific configuration: one flag, both backends, selected as `Renderer` already is.

## Verification

- Every phase: full build, `ctest -L host_quick`, `make arch-check`, `make docs-symbols`.
- Visual: the CLI harness (`--load <save> --tick N --screenshot --fixed-dt 16 --headless`) produces flag-off/flag-on pairs in the same interior/exterior spot on both backends; equivalence here is "identical to the eye and in diff", not byte-exact, because a flag-gated feature is allowed to prove itself rather than satisfy the ASM oracle — the software path with the flag off is what the oracle still guards.
- Each phase updates [RENDERER.md](../RENDERER.md) (and this plan's status) in the same commit; a phase is not done until the doc says what the flag does.

## Out of scope

- Menus, inventory and credits staying on the software path until Phase 4 says otherwise.
- Any change to the software rasterizers or their equivalence tests.
- Removing the readback before Phase 3 has moved every consumer of it.
- LBA1, editor builds and the holomap/credits body paths (they keep the software Log path, as they do now).
